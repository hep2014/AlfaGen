# Отчёты качества и производительности

Актуальные сохранённые отчёты — `quality-v4.json`, `performance-unique-final.json`
и `performance-mixed-5min.json`. Это измерения известных разработчику синтетических
регрессий и локальных профилей нагрузки. Они не подтверждают универсальное качество
распознавания или SLA на неизвестных текстах и другом оборудовании.

## Исторический срез v1

Воспроизводимый отчёт: `quality-v1.json`; входные файлы и методика описаны в
`data/synthetic/README.md`. Это измерение на искусственном наборе простых шаблонов,
не оценка качества на неизвестном датасете организаторов.

| Раздел | Примеры | TP / FP / FN | Precision | Recall | F1 | Точный roundtrip |
|---|---:|---|---:|---:|---:|---:|
| train | 214 | 161 / 0 / 48 | 100% | 77,03% | 87,03% | 214/214 |
| dev | 214 | 161 / 0 / 48 | 100% | 77,03% | 87,03% | 214/214 |
| test | 214 | 161 / 0 / 48 | 100% | 77,03% | 87,03% | 214/214 |
| challenge | 6 | 2 / 0 / 5 | 100% | 28,57% | 44,44% | 6/6 |

В срезе v1 13 поддерживаемых типов распознаны на явных полях этого набора.
Тогда ещё неподдерживаемые BIRTH_PLACE, CITIZENSHIP, PASSPORT_ISSUER, CARDHOLDER
остались в знаменателе полноты; правила для них добавлены в последующих срезах.
На test у 48 примеров остались непокрытые чувствительные символы, на challenge — у пяти.
Нулевые FP на маленьком шаблонном наборе не означают отсутствие ложных срабатываний вообще.

Этот отчёт зафиксировал необходимость добавления четырёх типов, свободной речи и падежей.
Подготовка независимого сложного набора с большим числом негативных контекстов остаётся
задачей: 95% качества на неизвестных данных не подтверждено. Внешняя LLM по умолчанию отключена.

## Срез v2

`quality-v2.json` сохраняет оценку того же датасета после добавления четырёх категорий,
«меня зовут» и ДР. Train/dev/test: TP=209, FP=0, FN=0 в каждом разделе; challenge:
TP=4, FP=0, FN=3, recall=57,14%, F1=72,73%. Roundtrip — 648/648.
Challenge теперь использован при разработке и является регрессионным, не закрытым набором.
Результат простых шаблонов 100% не подтверждает 95% на реальных текстах.

## Срезы v3 и v4 — 22 сентября 2026

Разметка v2 исключает служебные слова из чувствительных фрагментов и разбивает составные
паспортные и адресные значения на несколько спанов. Поэтому число TP в разделах
train/dev/test (259) нельзя напрямую сравнивать с 209 TP на разметке v1.

| Отчёт / раздел | Примеры | TP / FP / FN | Precision | Recall | F1 | Точный roundtrip |
|---|---:|---|---:|---:|---:|---:|
| v3, каждый из train/dev/test | 214 | 259 / 0 / 0 | 100% | 100% | 100% | 214/214 |
| v3, challenge | 6 | 4 / 0 / 3 | 100% | 57,14% | 72,73% | 6/6 |
| v4, каждый из train/dev/test | 214 | 259 / 0 / 0 | 100% | 100% | 100% | 214/214 |
| v4, challenge | 6 | 7 / 0 / 0 | 100% | 100% | 100% | 6/6 |

Между `quality-v3.json` и `quality-v4.json` в challenge-3 слово «года» исключено
из эталонного чувствительного фрагмента: `[15, 62)` → `[15, 57)`. Хеш challenge
изменился с `2944fd93…` на `d71f2786…`; хеши train/dev/test совпадают.
Рост challenge отражает и доработку детектора, и исправление разметки, а не только
улучшение распознавания. Challenge уже использован при разработке; название раздела
и оставшийся исторический тег `held_out_challenge` не делают его независимым holdout.
`quality-v3-legacy-labels.json` сохраняет оценку прежних границ со служебными словами.

Новый набор `robustness.py` также известен разработчику и используется для регрессий.
Точное восстановление само по себе не доказывает, что все чувствительные данные были
найдены и скрыты. Варианты и оставшиеся пробелы перечислены в
[разборе PDF и новых функций](../docs/pdf-review-and-features.md).

## Сохранённые профили производительности

| Отчёт | Соединения / фактическое время | Успешный RPS | p50 / p95 / p99, мс | Запросы / пары |
|---|---|---:|---|---|
| `performance-unique-final.json` | 200 / 3,199 с | 1519,9 | 109,9 / 250,5 / 292,9 | 4862 / 2431 |
| `performance-mixed-5min.json` | 200 / 300,727 с | 1899,4 | 96,5 / 227,2 / 304,1 | 571200 / 285600 |

В обоих отчётах ноль 429, транспортных ошибок и неверных результатов по проверкам
бенчмарка. Unique имеет 0 попаданий кеша; mixed — 285246 из 285600 (99,88%), так как
повторяет короткие положительные и отрицательные примеры. Сравнивать их как ускорение
одного и того же потока нельзя. Оба прогона используют один хеш исходников `0ab51287…`,
raw HTTP/1.1, один uvicorn-процесс на Windows и общий с клиентом компьютер. Они не включают
время внешней LLM, разгон нагрузки, длинные тексты или независимую проверку распознавания.
Оба отчёта предшествуют добавлению отдельного ограниченного пула крупных `/process`
и общего бюджета входящих буферов; они не описывают повторный прогон текущего кода.

Повторные замеры после компактного vault, retry-инструмента и отбора правил
(исторический хеш исходников `src/alpha_privacy` `8ec2fd5d…`; после исправления статических замечаний текущий хеш `1793b9c4…`):

| Отчёт | Соединения / время | Успешный RPS | p95 / p99, мс | Запросы / пары |
|---|---|---:|---|---|
| `performance-unique-current.json` | 200 / 10,108 с | 1168,5 | 392,6 / 431,5 | 11812 / 5812 |
| `performance-mixed-current.json` | 200 / 10,240 с | 1002,0 | 310,7 / 341,0 | 10261 / 5061 |
| `performance-dense-recheck.json` | 2 / 5,090 с | 10,02 | 431,5 / 447,0 | 51 / 25 |
| `performance-process-pool-memory-16.json` | 200 / 5,094 с | 1284,3 | 481,0 / 775,3 | 6563 / 3225 |
| `performance-process-pool-memory-16-current.json` | 200 / 5,243 с | 987,6 | 599,8 / 1089,5 | 5183 / 2540 |

В трёх исходных current-отчётах ноль 429, транспортных ошибок и неверных результатов;
новый профиль также не дал неверных результатов. `exhausted_pairs`
означает только пару, начатую перед окончанием короткой фазы, у которой второй шаг не был
допущен после дедлайна. Unique имеет ноль попаданий кеша. Плотный профиль содержит 22 000
различных email и проверяет расширение маски; это не 1000 RPS на длинных документах.
`performance-large-before-gates.json` сохраняет профиль до отбора правил: 3,85 успешных
RPS, p95 1467,7 мс, пять 429. Предыдущий большой прогон короткий и почти заполнил vault
(129088784 из 134217728 байт). Компактный `patch-v1` снизил занятый шифротекст на плотном
профиле до 61771320 байт для 26 живых пар; устойчивую пропускную способность на таких телах
он не подтверждает. Все прогоны выполнялись последовательно, на общей машине клиента и сервера.

`quality-recheck.json` повторяет метрики v4 на тех же хешах разметки v2. Полный набор
проверок текущего среза — 1104 passed; 377 из них проверяют эквивалентность отбора правил
полному поиску на длинных текстах. Это проверки регрессий, а не независимая оценка качества.

`performance-http.json` — более ранний прогон с HTTPX; `performance-raw-before.json`
и `performance-raw-inline.json` — короткое диагностическое сравнение до/после обработки
малых запросов без пула потоков. `performance-local.json` использует общий пул HTTPX;
разницу с raw нельзя целиком приписать оптимизации сервера. `performance-core.json`
измеряет отдельные операции, не пропускную способность всего сервиса.

Полная методика, команды повторного запуска и ограничения — в
[отчёте об устойчивости](../docs/resilience.md). Команды создают новые отчёты `*-recheck.json`,
чтобы сохранить исторические измерения.
