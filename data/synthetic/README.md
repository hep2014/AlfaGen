# Синтетический датасет v1

648 примеров: `train`, `dev`, `test` по 214 записей и `challenge` из 6 записей.
Каждый основной раздел содержит все 17 категорий. Значения построены локальным генератором
с seed `20260922`; внешние источники, реальные анкеты и внешняя LLM не использовались.

Email используют `example.org`, телефоны — вымышленный код `000`, адреса — Тестоград
и Вымышленную улицу. Документные/банковские номера намеренно учебные, без обещания валидных
контрольных сумм. Случайное совпадение имени или числового значения с реальным человеком
невозможно исключить, но записи не описывают реальных людей. Пушкин — контекстная ловушка:
упоминание поэта размечено как публичное, одноимённый вымышленный клиент — как PERSON.

## Формат

JSONL, одна запись на строку: `id`, `split`, `family`, `synthetic`, `tags`, `text`, `entities`.
Сущность: `start`, `end`, `type`, `value`. Интервал `[start,end)` задан индексами символов
Python (Unicode code points), не байтами и не UTF-16. При интеграции с JS нужны преобразования
для символов вне BMP. Знаки препинания вокруг значения не входят в интервал.
Внутренние пробелы/дефисы и разделители документа входят в интервал значения.

Разметка создаётся одновременно с текстом из типизированных фрагментов; она не выводится
из результатов детектора. Валидатор проверяет уникальность ID, границы, отсутствие
пересечений, категории и совпадение значения с срезом исходного текста.

## Разделение и ограничения

- `train`: явные поля с двоеточиями; для разработки правил.
- `dev`: анкеты, переносы, заголовки в верхнем регистре, значения в нижнем.
- `test`: обращения, поля без двоеточий, значения в верхнем регистре.
- `challenge`: свободная речь, падежи, дата словами, сокращение ДР, адрес без маркеров.

Это стартовый набор регрессий, **не независимый статистический benchmark**: разделы построены
общим генератором, используют одинаковые имена полей и повторяют некоторые значения.
Контекстные контрольные пары и негативные примеры намеренно повторены в основных разделах.
Их нельзя считать независимыми наблюдениями или использовать для заявления о качестве на
банковских текстах. Test не использовался для подгонки правил в этом срезе, однако шаблоны
созданы вместе с правилами. Challenge после первого измерения известен разработчику:
при доработке на нём он становится регрессионным, потребуется новый закрытый набор.

Датасет проверяет форматы, границы, регистр, принадлежность и восстановление. Пока не покрывает
полноценно OCR, Unicode-обфускации, все падежи, смешанные языки, все документы, 100k токенов,
раздельные компоненты адреса или диалоги. Малый отрицательный набор не доказывает низкую
частоту ложных срабатываний в реальном потоке. Для следующей версии нужны независимо
составленные сценарии и ручная проверка аннотаций человеком.

## Воспроизведение

Из корня проекта:

```powershell
.\.venv\Scripts\python -m alpha_privacy.synthetic
.\.venv\Scripts\python -m alpha_privacy.evaluate
```

Генерация перезаписывает четыре файла в `data/synthetic/v1`; оценка сохраняет
`reports/quality-v1.json`. Отчёт включает SHA-256 каждого входного файла, ошибки по ID
и метрики по каждому типу, включая неподдерживаемые категории.

Оценка использует точное совпадение типа и границ сущности. Precision без предсказаний
и recall без эталонных сущностей — `null`, а не искусственные 100%.
Счётчик непокрытых чувствительных символов отделён от точности классификации.
Roundtrip отдельно показывает точность восстановления, но не полноту защиты.

## Разметка v2

`v2` содержит те же 648 текстов; служебные слова внутри паспортов, адресов, мест рождения и дат вынесены за границы чувствительных фрагментов. Разметка строится явно генератором, без вызова детектора. Старый `v1` сохранён. Команда генерации по умолчанию теперь записывает `v2`.
