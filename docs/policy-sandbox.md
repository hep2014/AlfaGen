# Предварительный просмотр политики

`POST /v1/policies/preview` сравнивает действующую политику авторизованной системы с кандидатом на одном тексте. Нужны заголовки `X-System-ID` и `X-API-Key`. Текущую политику сервер выбирает по авторизации; передать другую систему или текущую политику в теле нельзя.

```json
{
  "text": "PIN 1234; email demo@example.org",
  "candidate": {
    "version": "draft-1",
    "detect_types": ["PIN", "CARD", "EMAIL"],
    "mode_by_type": {"EMAIL": "redact"},
    "combination_rules": [
      {"target": "PIN", "requires": ["CARD"], "max_distance": 128}
    ]
  }
}
```

Текст ограничен 16 384 символами. `candidate` проходит обычную валидацию `Policy`, включая допустимые режимы и зависимости комбинаций. Неизвестный тип возвращает 422 `unsupported_types`; ошибки структуры — 422 `invalid_request`. Служебный синтаксис `[[PD:` отклоняется, как при обычном маскировании.

Ответ содержит `current` и `candidate`: решения с позициями `start`/`end`, типом, режимом, причиной, признаками защиты и доступности восстановления. Позиции считаются в символах исходной строки, конец не включается. `protected_fragments` считает защищённые находки. `irreversible_fragments` включает `redact`, а также токены при `restore_enabled=false`, поскольку соответствие для восстановления в таком режиме не сохраняется. `session_ttl_seconds` показывается как настройка; песочница не проверяет работу хранилища или истечение TTL.

Обе политики выполняют собственный поиск с `detect_types` и затем ту же оценку `combination_rules`, что рабочий шлюз. Это сохраняет реальную семантику перекрывающихся находок. Дополнительный поиск по всем поддерживаемым типам создаёт `reference_findings`. `unprotected_reference_fragments` показывает открытые части этих находок. Исключённые из поиска категории перечислены в `excluded_types`.

`comparison.new_misses` содержит только участки известных чувствительных фрагментов, которые действующая политика защищала, а кандидат оставляет открытыми. Сравнение учитывает покрытие символов: защита другим типом также засчитывается, частично открытый фрагмент показывается точными границами. `fixed_misses` содержит обратное изменение. Это локальный предварительный просмотр относительно находок того же детектора; он не доказывает отсутствие ПД, полноту распознавания, качество на иных текстах или выполнение SLA. Находки детектора сами могут содержать пропуски и ложные срабатывания.

Для кандидата с `enabled=false` возвращается `status=system_disabled`: рабочий API не допустил бы запрос. Сравнение пропусков имеет `comparable=false` и поля `new_misses`/`fixed_misses` равны `null`; отказ в доступе не представляется утечкой или успешным маскированием.

Песочница не меняет действующую политику, не вызывает LLM, не создаёт маски, сеансы и записи в vault. Ответ не содержит исходных значений, текста, токенов или произвольного поля `version` кандидата. Аудит записывает только обычные сведения об операции. Штатный кэш детектора может сохранить HMAC-ключ и позиции находок без исходного текста. Эндпоинт `/process` продолжает использовать отдельную политику автопроверки с полным обнаружением и обратимостью.
