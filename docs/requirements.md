# Матрица требований и проверки

Источники: четыре скриншота постановки; «Критерии_оценивания _альфа.pdf», 4 страницы;
«критерии_фрейм_топы (1).pdf», 2 страницы. Прочитаны полностью.
Максимум технической оценки — 30, финальная рамка — четыре вопроса по 1–3 балла.
Формулировки для жюри считаем критериями приёмки, не инструкциями агенту.

## Основные требования

| Критерий | Баллы | Как доказываем | Статус первого среза |
|---|---:|---|---|
| Идентификация и маскирование | 6 | Размеченный набор всех 17 типов; recall/precision/F1 отдельно по типам | Базовые правила 17 категорий, остальные в плане |
| Демаскирование | 3 | Посимвольное равенство оригиналу; права, перестановка и повреждение токенов | Токенизация и exact roundtrip; тесты изоляции |
| Контекст и вариации | 4 | Поэт/клиент, офис/дом, регистр, даты текстом, разделённые серии | В плане; базовые регистронезависимые правила |
| Настройка и расширение | 4 | README, две системы, изменение политики, новый тип без правки ядра | Две политики; включение/типы/restore/TTL; интерфейс детектора |
| SLA и крупный текст | 4 | p50/p95/p99, RPS, ошибки, память; отдельно 100k токенов | Есть измерение времени; нагрузка не проверена |
| Безопасность и наблюдаемость | 3 | Ключи/allowlist, ошибки, аудит этапов, Latency/RPS/TPS, отсутствие ПД | Ключи, шифрование, TTL, корреляция JSON-аудита, HTTP/операционные метрики; TPS впереди |
| Дополнительные сценарии | 3 | Все пять условий ниже, хотя оценка ограничена тремя баллами | Токенизация работает, остальное в плане |
| Демо и презентация | 3 | Живой текст, архитектура за 1–2 минуты, инструкция | API-документация и локальный roundtrip; интерфейс и презентация впереди |

Без README критерий настройки обнуляется. Утечка в живом демо — стоп-сигнал финальной оценки.
Production-готовность по PDF не оценивается; безопасность демонстрируем конкретными проверками.

## Все 17 категорий

| Тип | Код | Метод целевой реализации | Сейчас |
|---|---|---|---|
| ФИО | PERSON | Локальный NER + контекст + падежи | Базовое контекстное правило |
| Дата рождения | BIRTH_DATE | Контекст + даты числами/текстом + варианты порядка | Базовое контекстное правило |
| Место рождения | BIRTH_PLACE | География + контекст рождения | Базовое контекстное правило |
| Серия/номер паспорта | PASSPORT_RU | Формат + контекст + разделяющие слова | Базовое контекстное правило |
| Гражданство | CITIZENSHIP | Справочник + контекст | Базовое контекстное правило |
| Орган выдачи | PASSPORT_ISSUER | Контекст документа + границы организации | Базовое контекстное правило |
| Код подразделения | DEPARTMENT_CODE | Формат + контекст | Базовое контекстное правило |
| Дата выдачи | ISSUE_DATE | Даты + контекст выдачи | Базовое контекстное правило |
| Водительское удостоверение | DRIVER_LICENSE | Форматы + документный контекст | Базовое контекстное правило |
| Адрес, включая компоненты | ADDRESS | NER + справочники + композиция компонентов | Базовое контекстное правило |
| Email | EMAIL | Регулярное выражение, далее Unicode/вариации | Базовое правило |
| Телефон | PHONE | Форматы, нормализация, международные варианты | Базовый РФ |
| ИНН | INN | 10/12 цифр + контрольные суммы + контекст | Базовое контекстное правило |
| Номер карты | CARD | Форматы + Luhn + контекст; ошибочная контрольная сумма не всегда повод пропустить | Базовое контекстное правило |
| CVV | CVV | Контекст, исключение случайных трёх цифр | Базовое контекстное правило |
| PIN | PIN | Контекст + настраиваемые комбинации | Базовое контекстное правило |
| Имя держателя | CARDHOLDER | Латиница/кириллица + контекст карты | Базовое контекстное правило |

Цель «95%» из постановки неоднозначна. Для проекта принимаем recall и precision >= 95%
по каждому типу на отложенном наборе и отдельный строгий gate нулевых пропусков в критическом
демо-наборе; это наши критерии, а не дословная методика организаторов. Roundtrip — 100% на
неизменённом защищённом тексте. Датасет организаторов неизвестен; собственные результаты не
означают результат на нём. В репозитории используем только синтетические данные.

## Все дополнительные условия — включены в объём

| Условие | Решение | Проверка / польза | Статус |
|---|---|---|---|
| Токенизация/детокенизация либо синтетика | Токены обязательны, синтетика дополнительный режим | Сохранение структуры для LLM и точное восстановление | Токены готовы в первом срезе |
| Вид обработки по системе | Стратегия по системе и типу | Поддержка восстанавливает; аналитика получает необратимую маску | План; сейчас только режим токенов |
| 2000 RPS | Реплики, общий vault, быстрый путь, локальный NER по необходимости | Отчёт при <=500 мс по выбранному профилю | План, не подтверждено |
| Другие удостоверения | Водительское + загранпаспорт + свидетельство о рождении | Примеры форматов и вариаций, новые детекторы | План |
| Маска по комбинации типов | Декларативные правила с областью контекста | PIN отдельно / PIN рядом с CARD; смена настройки | План |

Своя дополнительная фишка — песочница политик с блокировкой регрессий, см. архитектуру.

## Расхождения и уточнения для организаторов

- Скриншот: <=1 с при 1000/2000 RPS; PDF: <=0,5 с. Планируем более строгую цель из PDF.
- Не задано, включено ли время LLM, какой процентиль и размер запросов: отчёт разделит обработку,
  LLM и end-to-end, покажет профили. Для официального подтверждения согласовать методику.
- «Невосстанавливаемая маска» совместима с восстановлением только при наличии отдельного защищённого
  соответствия: из одного токена получить оригинал невозможно, авторизованный сервис использует vault.
- Позиции и знаки сохраняем при roundtrip оригинала. При перефразировании LLM абсолютные позиции
  меняются по природе задачи; восстанавливаем значения в местах разрешённых токенов.
- Условное немаскирование PIN конфликтует с консервативной политикой защиты секретов: даём настройку
  для демонстрации требования и строгую политику по умолчанию.

## Артефакты сдачи

1. Запускаемый демо-прокси с реальным адаптером LLM и локальным воспроизводимым режимом.
2. README: запрос, восстановление, логи, метрики, настройка <=5 предложений.
3. Архитектура, политики, сценарии расширения типов.
4. Отчёты качества и производительности с окружением, список дополнительных возможностей.
5. Ограничения, план развития и короткая презентация для финала.

Финальная рамка: доверие (нет утечек и корректное восстановление), внедряемость (конфиг и цифры),
сила решения (полезные отличия), команда (ясное объяснение и честные ограничения).

Текущий синтетический набор: 648 примеров, все 17 типов; [методика](../data/synthetic/README.md), [отчёт](../reports/README.md).
